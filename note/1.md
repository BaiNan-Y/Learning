## grpc

为什么不用grpc直接进行开发

- grpc 作为以http/2 作为底层逻辑的技术，其虽然名义上被浏览器所兼容，但其对浏览器的控制要求较高，但浏览器放出来的权限其实不够
  - Trailer 在 header、body 之外，grpc 还需要传递Trailer
  - 浏览器会对传递的信息进行魔改，例如添加相应状态码之类的，这些都是grpc所不允许的
- 实在需要的可以考虑使用 grpc-web 但没必要



## go-zero 

### 基础案例开发

```
https://go-zero.dev
```

go zero 和 kratos 类似，都参考了 go-kit 的开发思路，其都是 工具类开发思想，go-zero 要安装主要的 goctl 来进行全量的后续开发：

**goctl 安装**

```
go install github.com/zeromicro/go-zero/tools/goctl@latest
```

**利用 goctl 快速创建出可运行的 rpc 和 api 服务**

通过以下命令可以快速创建出一个rpc 和 api 服务

```
goctl rpc new rpc
goctl api new api
```

但是在实际开发中并不会直接这样创建，我们会依托 .proto 文件进行开发

我们先搞一个超简单的示例 user.proto

```protobuf
syntax = "proto3"; // 指定proto版本

package user; // 默认包名

// 编译命令
// protoc --go-grpc_out=require_unimplemented_servers=false:. --go_out=. ./user.proto

// 包名
option go_package = "./user";

// 定义服务名
service User {
    // 定义rpc方法
    rpc GetUser(GetUserReq) returns (GetUserResp);
}

message GetUserReq {
    // 属性的类型 属性名 = 标识符
    string id = 1;
}
message GetUserResp {
    string id = 1;
    string name = 2;
    string phone = 3;
}
```

之后运行如下命令即可生成 rpc 相关代码

```
goctl rpc protoc user.proto --go_out=. --go-grpc_out=. --zrpc_out=.
```

可以看到目录结构是

> rpc
>
> > etc（配置）（etcd配置文件）
> >
> > internal（核心代码）
> >
> > > **xxxlogic.gp（需要在这里定义核心的业务代码）**
> >
> > user（proto文件生成的grpc代码）
> >
> > userclient（对外接口）
> >
> > go.mod（自动生成，此处应该删除，go.mod 存在于微服务最外层即可）
> >
> > user.go （程序入口）
> >
> > user.proto

注：

```
go mod init xxx
go mod tidy
```

我们逻辑写清楚之后 `go run .` 就可以运行了，这里简单补充了一些逻辑：

```go
// 定义rpc方法
func (l *GetUserLogic) GetUser(in *user.GetUserReq) (*user.GetUserResp, error) {
	if u, ok := users[in.Id]; ok {
		return &user.GetUserResp{
			Id:    u.Id,
			Name:  u.Name,
			Phone: u.Phone,
		}, nil
	}
	return &user.GetUserResp{}, nil
}
```
