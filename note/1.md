## grpc

为什么不用grpc直接进行开发

- grpc 作为以http/2 作为底层逻辑的技术，其虽然名义上被浏览器所兼容，但其对浏览器的控制要求较高，但浏览器放出来的权限其实不够
  - Trailer 在 header、body 之外，grpc 还需要传递Trailer
  - 浏览器会对传递的信息进行魔改，例如添加相应状态码之类的，这些都是grpc所不允许的
- 实在需要的可以考虑使用 grpc-web 但没必要



## go-zero (这里是最关键的，新东西都是从这里出发的)

### 基础案例开发

```
https://go-zero.dev
```

go zero 和 kratos 类似，都参考了 go-kit 的开发思路，其都是 工具类开发思想，go-zero 要安装主要的 goctl 来进行全量的后续开发：

**goctl 安装**

```
go install github.com/zeromicro/go-zero/tools/goctl@latest
```

**利用 goctl 快速创建出可运行的 rpc 和 api 服务**

通过以下命令可以快速创建出一个rpc 和 api 服务

```
goctl rpc new rpc
goctl api new api
```

但是在实际开发中并不会直接这样创建，我们会依托 .proto 文件进行开发

#### rpc 部分

我们先搞一个超简单的示例 user.proto

```protobuf
syntax = "proto3"; // 指定proto版本

package user; // 默认包名

// 编译命令
// protoc --go-grpc_out=require_unimplemented_servers=false:. --go_out=. ./user.proto

// 包名
option go_package = "./user";

// 定义服务名
service User {
    // 定义rpc方法
    rpc GetUser(GetUserReq) returns (GetUserResp);
}

message GetUserReq {
    // 属性的类型 属性名 = 标识符
    string id = 1;
}
message GetUserResp {
    string id = 1;
    string name = 2;
    string phone = 3;
}
```

之后运行如下命令即可生成 rpc 相关代码

```
goctl rpc protoc user.proto --go_out=. --go-grpc_out=. --zrpc_out=.
```

可以看到目录结构是

> rpc
>
> > etc（配置）（etcd配置文件）
> >
> > internal（核心代码）
> >
> > > **xxxlogic.gp（需要在这里定义核心的业务代码）**
> >
> > user（proto文件生成的grpc代码）
> >
> > userclient（对外接口）
> >
> > go.mod（自动生成，此处应该删除，go.mod 存在于微服务最外层即可）
> >
> > user.go （程序入口）
> >
> > user.proto

注：

```
go mod init xxx
go mod tidy
```

#### api 部分

创建一个 user.api 文件

```go
syntax = "v1"

info (
	title: "用户服务api"
	desc:  "用户服务api的描述（这是一个用户服务的api）"
)

// 定义几个结构体来方便后续的操作
type (
	UserReq {
		Id string `json:"id"`
	}
	UserResp {
		Id    string `json:"id"`
		Name  string `json:"name"`
		Phone string `json:"phone"`
	}
)

// 货真价实的定义在这里
service User {
	// handler 这里是选择调用的方法（定义在 logic 中）
	// /user 是访问路径
	@handler user
	get /user (UserReq) returns (UserResp)
}
```

写完之后执行下面的指令：

```
goctl api go -api user.api -dir . -style gozero
```

就会生成对应的api 文件

> etc
>
> > user.yaml（etcd配置）
>
> internal
>
> > config
> >
> > handler
> >
> > logic（要在这个里面定义自己的业务逻辑）
> >
> > svc
> >
> > types

## 数据库

### 数据模型的生成

go-zero 的数据库处理方式也是 利用了goctl 的生成式方式，你需要在 .sql 文件所在的目录执行下面的指令：

```
goctl model mysql ddl --src user.sql --dir "./models/" -c
```

最后一个 -c 是为模型增加缓存

user.sql 是基于的sql文件，可以修改为 *.sql 则会给予当前目录下所有sql文件生成models 

基于这种形式生成的models 会直接具备基础的增删改查功能

### 启动项修改 - 添加数据库连接

修改文件：user / rpc / internal / svc / servicecontext.go

```go
package svc

import (
	"github.com/zeromicro/go-zero/core/stores/sqlx"
	"user/models"
	"user/rpc/internal/config"
)

type ServiceContext struct {
	Config config.Config

	// 添加我们需要放入的数据模型
	UserModel models.UsersModel
}

func NewServiceContext(c config.Config) *ServiceContext {
	// 创建合适的数据库连接
	sqlConn := sqlx.NewMysql(c.Mysql.DataSource)

	return &ServiceContext{
		Config: c,

		// 利用数据库连接将真实的数据模型注入
		UserModel: models.NewUsersModel(sqlConn, c.Cache),
	}
}
```

### 修改业务逻辑 - proto文件修改

例如添加一个新增的逻辑

```protobuf
syntax = "proto3"; // 指定proto版本

package user; // 默认包名

// protoc --go-grpc_out=require_unimplemented_servers=false:. --go_out=. ./user.proto

    string phone = 3;

message CreateReq {
    string id = 1;
    string name = 2;
    string phone = 3;

    // 定义rpc方法
```
